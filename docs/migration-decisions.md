# GeoCluster desktop → API migration decisions

Scope: `api/` only. Nothing under `desktop/` was modified, and the desktop app
remains fully functional. This document records every semantic choice, every
place the two desktop implementations disagreed, and everything intentionally
not ported.

## 1. Which desktop code is canonical

The desktop has **two** processing implementations:

* `desktop/frontend/ui.py` — what users actually run (cv2-based, alpha-aware).
* `desktop/frontend/backend_py.py` — a second, subtly different copy used
  through the file-IPC path.

Both were read end to end. Per the task, **ui.py wins wherever the two
disagree**; every API filter therefore reproduces ui.py exactly and the
disagreements below are locked by golden fixtures.

| Operation | ui.py behavior (ported) | backend_py.py behavior (NOT ported) |
| --- | --- | --- |
| grayscale | `to_grayscale`: 2-D unchanged; BGRA drops alpha then `cv2.COLOR_BGR2GRAY` | `grayscale_copy` just copies the array |
| negative | `cv2.bitwise_not`, **alpha preserved** for BGRA | `255 - image` on the whole array (inverts alpha too) |
| brightness | `int16` add + clip, **alpha preserved** for BGRA | `int32` add + clip on the whole array |
| threshold | `cv2.threshold(..., THRESH_BINARY)`; BGRA thresholds BGR only, alpha preserved | `np.where(image > t, 255, 0)` on the whole array |
| mean filter | `cv2.blur` (default reflected border) | custom `_reflected_indices` border handling |
| laplacian | `convertScaleAbs(cv2.Laplacian(gray, CV_64F))` (grayscale output) | not implemented |
| statistics | `np.min/max/mean/std` on `to_grayscale(image)`; the UI shows 2 decimals | – |
| k-means | driven from `execute_operation` → `process_operation` → `run_kmeans` | `run_kmeans` itself (algorithm source of truth) |

Golden fixtures (`api/tests/fixtures/`) were generated by importing the desktop
modules directly; the tests compare pixel-for-pixel, so any future drift in
the API is caught.

## 2. K-Means

Ported from `backend_py.run_kmeans`, torch replaced by NumPy, double precision
throughout:

* initialization: centroid of each initial range `(low + high) / 2`, where the
  ranges are the UI's `calculate_default_ranges(k)` (even 0..255 buckets);
* assignment: nearest centroid per intensity through a 256-entry LUT
  (first-minimum tie-break) — the histogram formulation;
* update: centroid = mean of its members; empty clusters keep their centroid;
* convergence: `max |new - old| < 0.5`, default `max_iter = 30`;
* output ranges: midpoints of sorted final centroids; first starts at 0, last
  ends at 255;
* output labels: pixels are labeled by the **final ranges** (the same masking
  pass as the desktop's `output[mask] = cluster_index`), stored as uint8 —
  identical in meaning to the desktop's `output.csv`.

All sums are integers below 2^53 written in float64, so accumulation order
cannot change the result; the port is bit-identical to torch semantics.

*Not ported:* the desktop clamps K to `2..60` inside the backend dispatcher;
the UI dialog only offers `2..20`, which is what the API validates.
The UI's `algorithm_ranges`/`current_ranges` bookkeeping (undo/redo and the
six-cluster substitution quirk on reload) is presentation state, not part of
the algorithm.

**Fixture caveat (important):** torch is not installable in the build sandbox
(PyPI and `download.pytorch.org` unreachable), so the K-Means fixture was
produced by a deliberately naive reference implementation of `run_kmeans`
(per-intensity loops, per-cluster sums) — *not* by torch. Provenance is
recorded in `api/tests/fixtures/expected_values.json` →
`kmeans_k5.generator`, and the port under test is a different, vectorized
implementation, so the comparison is still independent.

## 3. Classification / legend

* Range → color recoloring follows `ui.apply_cluster_assignments` (mask per
  inclusive range, paint the cluster color) and writes **BGR** into the
  display image, exactly like the desktop preview (`numpy_to_pixmap` converts
  BGR→RGB for Qt; a PNG saved from the same array shows the intended colors).
* Label → color preview follows `ui.build_cluster_display_image`.
* Legend percentages follow `ui._recalculate_counts` and `ui.generate_map`:
  count of pixels inside each inclusive interval, `round(count/total*100, 1)`,
  plus the `"Name-P.P%"` label used in generated maps.
* The curated six-cluster preset (`SIX_CLUSTER_DEFAULTS`: names, colors and
  0..69/70..85/86..130/131..145/146..216/217..255 ranges) is reproduced, as is
  the HSV fallback palette for other counts. `qt_hsv_to_rgb` reproduces
  `QColor.fromHsv(h, 180, 220)` exactly — verified against PyQt5 for **all 360
  hues** during fixture generation — because the desktop uses Qt for that
  palette.
* The unused `method` parameter of `default_cluster_assignments` was dropped
  (the desktop function ignores it too).

## 4. Huffman (GCH2)

* GCH2 only. **GCH1 is intentionally not ported** (dead in the desktop).
* Format is byte-compatible: `"GCH2"` + `<IIIII>` (rows, cols, channels,
  payload_bits, version=1) + 256 little-endian uint32 frequencies + MSB-first
  packed payload, final byte zero-padded.
* Prefix codes are built with the desktop's exact heap/ordering semantics, so
  the API output for a given image is **byte-identical** to the desktop's file
  (locked by a test against the desktop-generated `.gch` fixture).
* Bit packing is vectorized with NumPy. Decoding uses a per-state byte
  transition table (8 bits per lookup) with the tail byte walked bit-by-bit;
  this is not a pure bit-parallel decoder because Huffman decoding is
  inherently sequential, but it is ~1.2 s for the 1.7 MP desktop fixture and
  ~2.4 s for a worst-case 4 MP noise image (12 M symbols) — measured, see the
  report in the repository history.
* Corrupt/truncated/absurd-header files raise `HuffmanError` → HTTP 400.

## 5. File IPC removed

`params.txt`, `output.csv`, `centroids.txt`, `ranges.txt`, `output_meta.txt`,
`huffman.bin`, `data/cache/` and every fixed path from `config.py` are gone.
Processing is in-memory function calls; `tempfile` is used only by the
satellite cache. The desktop's `read_centroids`/`read_ranges`/`parse_metadata`
deserializers are not ported.

## 6. Satellite

* **One cache-key rule** (the desktop's `fetch_sector_image` rule):
  `strip() → upper() → " "→"_" → "/"→"_"`, then `.png`. E.g. `"nust h12"` →
  `NUST_H12.png`. Documented and tested as the single rule.
* Cache directory is configurable (`SATELLITE_CACHE_DIR`), defaulting to a
  folder under the OS temp directory (`%TEMP%/geocluster-satellite-cache`).
* Date range is optional per request; the default window is **rolling and ends
  today** (61 days, matching the old hardcoded window's length) instead of the
  desktop's frozen `2026-05-01 … 2026-07-01`.
* OAuth token is cached for under 10 minutes (`min(expires_in − 30 s, 540 s)`)
  and is never logged or returned; credentials come from the environment only.
  Missing credentials do **not** fail startup — the endpoint answers 503.
* Unchanged from the desktop: token/process URLs, request payload, the
  `leastCC` mosaicking order, the true-color evalscript and the native
  resolution calculation.
* Upstream failures → 502 (generic message, detail logged server-side);
  unknown location → 404.

## 7. Assistant

* `CommandRouter` and the Fireworks wrapper are ported as-is: same model
  (`accounts/fireworks/models/qwen3p7-plus`), same base URL, same system
  prompt, same `temperature=0.3`, `max_tokens=150`, `extra_body={
  "reasoning_effort": "none"}` and the same `clean_response` post-processing.
  The known expired-credits/provider issue was **not** touched.
* Allowed changes only: constructing `AIAssistant` never raises (an
  `available` flag drives 503), and provider failures raise
  `AssistantProviderError` → HTTP **502** with a generic message while the
  full error is logged server-side. A raw `"Error code: 404 …"` string can
  never appear in a 200 response.
* SDK version: the desktop pins `openai==2.45.0`, the API pins
  `openai==3.22.1`. The desktop call shape is smoke-checked against the
  installed 3.22.1 SDK with a mocked HTTP transport: `temperature`,
  `max_tokens` and `extra_body` are accepted and `extra_body
  (reasoning_effort)` is forwarded verbatim in the request body, and the
  response parses identically. **No API differences were found** for this
  call shape; the test lives in `api/tests/test_assistant.py`.
* Router quirks are preserved, including the desktop's ordering quirk that
  `"show histogram"` routes to `fetch_satellite` (satellite verbs are matched
  before the operation map). Both the quirk and every operation/intent the
  router can emit have tests.
* The three operations the desktop router emitted but never executed now
  produce structured commands for the client: `histogram` →
  `{"action":"open_histogram"}`, `compress` → `{"action":"open_compress"}`,
  `distance` → `{"action":"open_distance"}`. Executable operations produce
  `{"action":"run_operation","operation":…}`; satellite requests produce
  `{"action":"fetch_satellite","location":…}`.

## 8. API-era additions (not present in the desktop)

* In-memory sessions: opaque ids, sliding TTL (default 60 min), per-session
  image cap (default 6, least-recently-used eviction), global memory budget
  (default 512 MB) that evicts globally LRU images and answers **507** when a
  single image cannot fit. Nothing is persisted.
* `dependencies.require_auth` is a no-op dependency attached to every router —
  the single hook to add auth later.
* In-process sliding-window rate limiting on `/ai/chat` (default 10/min) and
  `/satellite/fetch` (default 5/min) → 429 + `Retry-After`.
* Upload validation by **content**: magic-byte sniffing (JPEG/PNG/BMP/TIFF)
  plus an actual decode; file extensions are never trusted (a JPEG named
  `.txt` is accepted, a GIF is rejected). Size cap enforced while streaming.
* Downscale policy: images above `MAX_IMAGE_MEGAPIXELS` are resized with
  `cv2.INTER_AREA`; dimensions use `floor(sqrt(cap/mp) · dim)` so the result
  can never exceed the cap; the response reports original size, stored size
  and the scale factor.
* Decoding mirrors `ui.load_image` (`cv2.IMREAD_UNCHANGED`, so grayscale and
  alpha survive). Non-uint8 inputs are normalized: uint16 → `//257`, int16 →
  clip, float → `×255` if the peak is ≤1 else clip. Documented policy.
* Status codes: 201 created, 400 bad Huffman payload, 404 unknown
  session/image/operation/location, 413 too large, 415 unsupported/undecodable
  image, 422 invalid parameters, 429 rate limited, 502 provider failure,
  503 not configured, 507 memory budget exhausted. Errors are always
  `{"detail": …}` — never error text inside a 200.
* New modules beyond the requested tree, each small and documented:
  `settings.py` (env configuration), `dependencies.py` (auth hook + store
  accessors), `ratelimit.py`, `uploads.py` (capped streaming read),
  `geocluster/errors.py` (exception hierarchy), `geocluster/data/`
  (verbatim copies of the two Islamabad JSON files, so the package is
  self-contained).

## 9. Intentionally not ported

* The PyQt5 UI itself (`ui.py` window/widgets/dialogs, `app.py`), including
  undo/redo stacks, the distance tool UI, pixel-hover readout and view sync.
* Matplotlib histogram window and map/legend rendering (the API returns the
  256-bin counts and the legend data instead).
* GCH1, the file-IPC layer, `process_operation`, the `Timer` logging helper
  and `write_csv_matrix`/`read_csv_matrix`.
* `torch` (never needed: the algorithm is a 1-D histogram method), `PyQt5`,
  `matplotlib`, `pillow` — the API requirements contain none of them.
* Dockerfile/deployment config, databases, job queues, auth.

## 10. Known limitations / deviations

* K-Means fixtures were reference-generated, not torch-generated
  (see §2) — the one place where the "call the desktop code" instruction could
  not be followed literally.
* The synthetic 4 MP timing image has near-maximum entropy, so its Huffman
  `compressed_bytes ≈ original_bytes`; real photographs compress much better
  (the desktop sample: 5.12 MB → 4.91 MB).
* The API is synchronous. Measured worst case on 4 MP: K-Means 0.40 s,
  Huffman compress 0.84 s, decode 2.36 s — all well under the ~10 s budget, so
  no job queue was added.
